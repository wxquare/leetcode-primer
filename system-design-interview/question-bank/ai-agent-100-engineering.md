# AI 与 AI Agent 工程面试 100 题

面向 AI 应用、LLM 与 Agent 工程岗位，覆盖模型基础、上下文、知识、工具、执行状态、可靠性、评测、安全和端到端架构。训练重点是根据业务约束作出决策，并解释如何验证、恢复与演进。

## 定位与优先级

- **P0 必答：** 核心机制、授权边界、业务正确性和基本失败处理。
- **P1 高频：** 性能、恢复、评测、发布与运维闭环。
- **P2 深入：** 推理基础设施、大规模检索和复杂编排的取舍。

优先级与题型独立。90 道专项题建议每道练习 5–10 分钟；10 道核心案例建议每道练习 35–45 分钟。核心案例为第 21、56、71、80、95–100 题，不要求一次读完整个题库。

## 通用答题方法

先说明用户目标、成功标准、非目标和允许的动作，再展开下面六步：

1. **约束：** 明确延迟、任务时长、预算、数据时效、租户与风险等级。
2. **规模：** 从请求量推导模型调用、Token、工具调用、并发和存储增长。
3. **状态：** 区分业务权威事实、执行记录、生成结果、记忆与检索索引。
4. **主链路：** 说明同步承诺、异步步骤、授权检查、验证与完成条件。
5. **失败：** 处理超时、未知结果、重复、断线、取消和依赖失效。
6. **取舍：** 用质量、成本、延迟和恢复指标验证方案，给出演进条件。

业务系统保存订单、权限和账户等事实；任务存储保存执行进度；知识索引与缓存是派生数据。模型输出和自然语言记忆不能替代这些权威状态。

容量估算应声明统计窗口和假设，不把平均值当作峰值保证：

```text
模型调用率 ≈ 任务到达率 × 每任务平均模型调用数（包含重试）
输入/输出 Token 速率 = 模型调用率 × 对应平均 Token 数
执行中任务数 ≈ 稳态任务到达率 × 平均执行时间
工具压力 = 任务到达率 × 每任务工具调用数（包含扇出与重试）
```

这些是初始估算。容量验证还需覆盖长输入、长输出、突发、慢依赖、租户热点和恢复流量；预算覆盖模型、Embedding、Rerank、工具、存储与评测。

## 练习指南

### 候选人训练

专项题按“结论、理由、适用边界”回答，再处理一次约束变化。核心案例先建立基线，只画必要边界、状态和主要依赖，然后处理故障注入。

每轮记录一个可验证改进动作，例如“下次先定义工具结果未知状态”，并在同一案例的变体中验证。不要只记录“继续熟悉 RAG”这类无法观察的目标。

### 面试官评估

| 观察点 | 可接受表现 | 深入表现 |
| --- | --- | --- |
| 目标与约束 | 问出会改变方案的条件 | 排序质量、延迟、预算与风险 |
| 权限与事实 | 区分模型建议和业务授权 | 说明执行前检查及事实核验 |
| 主链路 | 描述检索、模型、工具与状态 | 说明同步承诺及结果未知状态 |
| 失败恢复 | 回应具体故障 | 给出执行权、幂等、对账与人工边界 |
| 验证与演进 | 说明如何测质量与性能 | 给出切片、发布门禁与演进条件 |

追问一次只改变一个条件；不按是否提到某框架、向量库或消息队列评分。

### 练习路线

入门先练 1–20、36–40、46–49 和 89；应用工程重点练 21–35、56–74、81–94；资深岗位再练 75–80 和 95–100。每轮组合一道机制题、一道失败处理题和一道核心案例。

## 1. LLM 基础与技术选型

#### 1. Transformer 核心组成与工程影响

**题型：** 专项题，P0

##### 题干与约束

解释常见 Decoder-only 语言模型从输入 Token 到输出分布的过程，并说明哪些结构影响推理成本。

##### 答案骨架

1. Token 经 Embedding 和位置相关机制进入多层 Block，最后由输出层产生下一 Token 的 logits。
2. Attention 通过 Q/K/V 建模上下文关系，多头关注不同表示；因果约束防止读取未来 Token。
3. FFN 逐位置变换表示，Residual 与归一化帮助信息和梯度传播；具体顺序依架构而异。
4. Attention、FFN 和 KV Cache 共同影响计算与内存开销，不能仅凭参数量判断延迟。

##### 递进追问

输入长度翻倍时，为什么不能断言总耗时恰好翻倍？

##### 常见失分点

把所有 Transformer 都说成自回归模型；只背模块名称；忽略位置、Mask 和实现差异。

#### 2. Token 与可用上下文窗口

**题型：** 专项题，P0

##### 题干与约束

多轮工具任务不断超出上下文限制，如何估算并管理可用窗口？

##### 答案骨架

1. Token 是模型输入输出的基本单位。了解 BPE、WordPiece 与 SentencePiece 等分词算法或工具，但实际计数使用目标模型的 Tokenizer 或供应商能力，中文字符与 Token 没有固定一一对应关系。
2. 统计规则、历史、工具声明、证据、结果与输出预算；部分接口另有输出或推理预算。
3. 先预留生成空间，再按任务优先级选择输入；超限前裁剪、摘要或检索。
4. 监控截断率、任务成功率、输入长度与成本，窗口能容纳不代表能有效利用。

##### 递进追问

工具返回突然增大十倍，哪些内容应保留，哪些可以转为引用？

##### 常见失分点

只计算用户消息；按字符数精确计费；把标称窗口全部用于输入。

#### 3. Embedding 与文本相似度

**题型：** 专项题，P0

##### 题干与约束

解释文本 Embedding 的用途，以及相似检索为什么不能证明答案相同。

##### 答案骨架

1. 文本编码器把句子或段落映射到向量空间，用于检索、聚类、去重和路由，与内部 Token 表示的使用方式不同。
2. 按模型训练方式选择余弦、内积或距离，确认是否需要归一化，不能任意替换。
3. 相似度不是事实正确概率；否定、时间、数值和主体变化可能改变答案。
4. 固定模型与预处理版本，用领域查询评估；不同模型空间通常不能混用。

##### 递进追问

两个模型输出维度相同，为什么仍不能直接在同一索引里比较？

##### 常见失分点

把维度当质量指标；所有向量都强制归一化；把相似度当置信概率。

#### 4. LLM 生成的 Prefill 与 Decode

**题型：** 专项题，P0

##### 题干与约束

用户反馈“第一段很慢”和“每个字都很慢”，如何解释两类延迟？

##### 答案骨架

1. 常见自回归推理先处理输入完成 Prefill，再迭代 Decode 生成后续 Token。
2. TTFT 包含排队、网络、预处理和 Prefill；TPOT 描述后续 Token 生成间隔。
3. 输入长度、调度与缓存影响首 Token，输出长度与 Decode 速度影响完成时间。
4. Decode 在不少场景受内存带宽制约，实际瓶颈还与模型、硬件和批量有关。
5. 输出上限只限制生成长度，不保证准确长度；截断可能破坏 JSON 或工具参数，需检查结束原因。

##### 递进追问

开启流式后首屏更快但总耗时不变，如何解释？

##### 常见失分点

把流式等同于推理加速；混淆 TTFT 与总耗时；忽略排队。

#### 5. 幻觉、忠实度与拒答

**题型：** 专项题，P0

##### 题干与约束

助手给出了语气确定但不存在的政策，如何定义问题并治理？

##### 答案骨架

1. 区分符合事实、由证据支持，以及证据是否最新且适用。
2. 用可信检索、来源版本、引用校验与业务规则减少无依据结论，RAG 不保证消除幻觉。
3. 证据不足时澄清、说明缺口或拒答，高影响决策设置人工复核边界。
4. 分别统计事实错误、无依据扩展和虚构引用，模型自报置信度需校准。

##### 递进追问

忠实复述过期文档，为什么仍可能是错误答案？

##### 常见失分点

只降低温度；用模型自信替代证据；把引用存在当成支持结论。

#### 6. 采样参数与可复现性

**题型：** 专项题，P1

##### 题干与约束

相同输入偶尔得到不同结果，Temperature、Top-p、Top-k 和 Seed 能保证什么？

##### 答案骨架

1. Temperature 改变分布锐度，Top-p 按累计概率选候选，Top-k 按数量截断，支持情况依接口而异。
2. 固定 Seed 和低温可减少随机性，不能保证跨版本、调度和计算环境逐字复现。
3. 固定输入、模型与配置，记录依赖结果；稳定格式由契约和校验保障。
4. 业务幂等保存首次有效结果，不能靠再次生成相同文本实现。

##### 递进追问

Temperature 为零仍有差异，应记录哪些版本和输入？

##### 常见失分点

把 Seed 当承诺；认为低温保证正确；只比较文本而忽略业务结果。

#### 7. Prompt、RAG 与 Fine-tuning 的取舍

**题型：** 专项题，P0

##### 题干与约束

格式不稳定、私有知识缺失和成本过高同时出现，如何选择手段？

##### 答案骨架

1. 建立基线与错误分类，判断来自行为、知识、模型能力还是系统链路。
2. Prompt 与输出约束适合调整规则、示例与格式；RAG 提供可更新、可追溯的外部知识。
3. Fine-tuning 学习任务行为、格式和领域模式，需要数据、训练与回归投入，知识更新不自动发生。
4. 三者可组合，按收益与维护成本判断次序，不把“先 RAG 后微调”当普适规则。
5. 微调数据需覆盖任务分布并隔离验收集，评估过拟合、遗忘及工具行为回归；权限仍由应用执行。

##### 递进追问

知识完整但工具选择持续错误，为什么加文档可能无效？

##### 常见失分点

用微调代替实时查询；声称任何微调都不影响知识；缺少数据和评测依据。

#### 8. KV Cache 与长上下文

**题型：** 专项题，P1

##### 题干与约束

长对话并发增加后显存不足，KV Cache 的收益与代价是什么？

##### 答案骨架

1. KV Cache 复用已处理 Token 的 Key/Value，减少 Decode 重复计算。
2. 缓存量与层数、KV 头数、头维度、Token 数、并发及数据类型有关。
3. PagedAttention 等分页管理、KV 量化、合理上下文和调度改善资源使用，需验证兼容与质量。
4. 批处理不意味着任意请求共享 KV；受支持的共同前缀才有额外复用机会。

##### 递进追问

两个请求只有后半段相同，为什么不能直接当共同前缀命中？

##### 常见失分点

把 KV Cache 等同于答案缓存；认为 Batching 自动共享历史；只估权重。

#### 9. 模型选型与业务基线

#### 10. 自托管与模型 API 的边界

**题型：** 专项题，P2

##### 题干与约束

企业要求数据可控且流量峰谷明显，应自托管还是使用模型 API？

##### 答案骨架

1. 明确传输、留存、访问、部署位置与审计要求，自托管不自动等同安全。

平均 GPU 利用率低而峰值等待严重，应比较哪些成本？

##### 常见失分点

只比较 Token 单价；私有部署不做权限治理；遗漏维护投入。

#### 12. Few-shot 与分步推理

**题型：** 专项题，P0

##### 题干与约束

复杂分类中，如何使用示例与分步推理，并控制成本？

##### 答案骨架

1. Few-shot 展示映射、边界与格式，优先覆盖真实困难样本。
2. 显式分析或模型内部推理可能改善复杂任务，按模型能力与评测选择。
3. 不依赖完整内部思维链作审计证据，要求可核验依据、简短解释或验证结果。
4. 测试数量、顺序与分布影响，防止示例污染留出集。
5. 可用多次采样的一致性、独立校验或反思评估提升空间，同时计入额外 Token 与时延；重复赞同不等于正确。

##### 递进追问

示例都来自同一类别，模型偏向它时如何验证原因？

##### 常见失分点

认为“逐步思考”必然有效；推理文本当证明；堆砌示例。

#### 13. 结构化输出与业务校验

##### 常见失分点

#### 14. Function Calling 的执行责任

**题型：** 专项题，P0

##### 题干与约束

解释工具声明到结果回传的过程，模型与应用各负责什么？

1. 应用提供名称、描述与 Schema，模型生成调用建议与参数。

同时建议“查余额”和“扣款”，为什么不应一律并行？

##### 常见失分点

建议当执行成功；模型判断权限；遗漏结果关联。

#### 15. SSE 流式输出协议

**题型：** 专项题，P1

##### 题干与约束

设计可区分内容增量、步骤进度、错误与完成的输出流。

##### 答案骨架

1. 使用 `text/event-stream` 与事件类型，区分增量、状态和最终结果，分配事件 ID。
2. 验证代理缓冲、超时与心跳，定义终态事件和客户端关闭行为。
3. SSE 是服务端到客户端通道，取消另走接口；原生 EventSource 与 fetch 流的重连机制不同。
4. 共享事件或结果存储支持多副本恢复，不天然依赖粘性路由或 WebSocket。

##### 递进追问

完成事件已发出但前端没收到，如何确认最终状态？

##### 常见失分点

TCP 分片当事件；断线当取消；只有增量无终态。

#### 16. Prompt 版本管理与 A/B

## 3. RAG 与知识工程

#### 21. 企业 RAG 全链路设计

**题型：** 核心案例，P0，45 分钟

##### 目标与规模假设

十万份持续更新的文档提供带引用问答，峰值每秒 30 个问题，用户权限不同。规模仅作练习假设，需澄清文件大小、更新率与延迟目标。

##### 不可协商约束

- 无权内容不能进入用户可见答案、引用与共享缓存。
- 来源版本和处理状态可追踪，证据不足不编造政策。
- 源文档是内容权威，索引是可重建的派生数据。

##### 关键决策

离线与在线边界；权限与索引协同；检索、重排、生成预算。

##### 答案骨架

1. 接入文档及版本，异步解析、分块、Embedding、建立索引，记录阶段状态与血缘。
2. 在线鉴权、改写、混合召回、重排，组装带定位证据，生成并核验引用。
3. 更新与删除采用幂等事件、版本保护与缓存失效，发布完整版本并暴露新鲜度。
4. 分层评测解析、召回、忠实度与成功，监控积压、撤权延迟、费用和尾延迟。

##### 故障注入

文档撤权但索引未同步；处理完这一故障后，再假设新版本解析失败。分别说明阻止越权、标识缺口与恢复方案。

##### 评价要点

区分内容、权限、索引与答案责任，说明失败承诺及重建验证。

2. HNSW、IVF、PQ 在内存、训练、压缩和更新上各有取舍，以目标负载测试。
3. 设计分片、热点隔离与归并，检查过滤结合 ANN 后的召回。
4. 验证可见性、删除、备份与重建；小规模或强过滤场景也可评估 MySQL、Elasticsearch 等已有存储能力。
5. 以访问热度设计冷热层与容量余量，监控召回、过滤后候选数、索引大小、资源和重建进度。

##### 递进追问

过滤只剩很少候选，ANN 不足时如何补救？

##### 常见失分点

向量库自动租户隔离；只测无过滤；无恢复。

#### 26. 混合检索与 Rerank

**题型：** 专项题，P0

##### 题干与约束

问题同时含产品 ID 和语义描述，如何融合检索？

##### 答案骨架

1. BM25 补精确术语，向量补语义与改写，两者都需验证领域效果。
2. 去重后用 RRF 或经校准的分数融合，原分数不可直接同量纲相加。
3. 对有权限候选重排，限制数量、长度与延迟。
4. 分别测召回、排序和生成，收益超过成本才引入复杂链路。

##### 递进追问

重排提高质量但 P99 超标，如何分级启用？

##### 常见失分点

直接加分数；无候选上限；视作所有场景标配。

#### 27. 查询改写与多跳检索

**题型：** 专项题，P1

##### 题干与约束

“那项政策也适用于海外吗”如何利用历史而不改变意图？

##### 答案骨架

1. 解析指代形成独立查询，保留原始问题与改写记录。
2. 检查实体、时间、否定与地域，缺信息先澄清。
3. 拆多跳子查询，携带证据与依赖，防止早期错误放大。
4. 限制查询数与 Token，比较原查询效果并支持回退。

##### 递进追问

改写新增用户未指定的年份，如何检测？

##### 常见失分点

假定无损；无限扩展；丢失意图。

#### 28. 检索置信与无答案处理

**题型：** 专项题，P0

##### 题干与约束

任何问题都有 Top-k，如何判断证据足够？

##### 答案骨架

1. Top-k 仅是候选，检查相关性、答案覆盖、时间与来源。
2. 用可回答与无答案样本校准阈值，按域评估误答与误拒。
3. 不足则澄清、有界再检索或拒答，相似度不直接当概率。
4. 记录拒答原因与反馈，不只奖励回答数量。

##### 递进追问

证据没有覆盖问题中的例外条件，能否直接回答？

##### 常见失分点

通用固定阈值；失败都返回通用答案；只优化回答率。

#### 29. 引用生成与证据校验

**题型：** 专项题，P0

##### 题干与约束

链接存在但原文不支持结论，如何治理？

##### 答案骨架

1. 证据分配标识，保存版本与位置，模型从允许集合选引用。
2. 校验存在、可访问、版本与定位，拒绝编造链接。
3. 关键主张核验语义支持，链接有效不等于结论有依据。
4. 冲突来源展示范围与时间，高影响结论规则或人工复核。

##### 递进追问

源文档更新后，历史答案应指向哪个版本？

##### 常见失分点

只检查 URL；自由生成来源；无版本。

#### 30. 知识更新与一致性

**题型：** 专项题，P1

##### 题干与约束

更新、删除与乱序事件中如何避免旧知识残留？

##### 答案骨架

1. 以源版本驱动处理，记录接入到发布阶段状态。
2. 幂等消费与版本比较拒绝倒退，删除使用墓碑或等效保护。
3. 缓存绑定知识版本；关键删除和撤权可先用在线检查阻断。
4. 对账与暴露延迟，坏版本回退不能撤销删除或撤权要求。

##### 递进追问

V3 发布后 V2 任务晚到，如何防止覆盖？

##### 常见失分点

只靠 TTL；无乱序保护；删除只移除源文件。

#### 31. RAG 权限过滤与撤权

**题型：** 专项题，P0

##### 题干与约束

同一问题各用户可见文档不同，如何防越权？

##### 答案骨架

1. 按用户、租户与当前授权构造范围，证据进模型前完成访问检查。
2. 预过滤与后过滤有性能取舍，未授权候选不得进入模型或用户输出。
3. 重排、引用、缓存、历史答案与产物复用执行同样的隔离。
4. 撤权有生效窗口，高敏感场景交付前复核，索引延迟不默认放行。

##### 递进追问

生成过程中撤权，尚未交付的结果如何处理？

##### 常见失分点

只前端隐藏；不区分后过滤发生位置；忽略缓存。

#### 32. RAG 分层评测

**题型：** 专项题，P0

##### 题干与约束

Recall@K 提高而满意度下降，如何定位？

##### 答案骨架

1. 检查解析和答案覆盖，明确 Recall@K、MRR 等指标的标注单位。
2. 生成测正确、忠实、完整、引用与拒答，指标不能互相替代。
3. 业务测解决率、转人工、耗时与成本，按语言、权限与无答案切片。
4. 固定版本检查噪声、重排与预算，在线反馈配合人工抽样。

##### 递进追问

更多相关文档稀释关键证据，如何做对照实验？

##### 常见失分点

单分数代表全链路；无无答案样本；相关块当完整答案。

#### 33. 长上下文与 RAG 的组合

**题型：** 专项题，P1

##### 题干与约束

500 页文件用于查规定或总结全文，如何选路径？

##### 答案骨架

1. 局部查询定位证据，全局总结与比较可能需分层阅读或长上下文。
2. 比较预算、覆盖、位置敏感、延迟与成本，不用页数直接决定。
3. 检索后扩展章节，或分段分析汇总，保留完整性与来源检查。
4. 处理权限、更新、截断和不可读页面。

##### 递进追问

总结遗漏附录例外条款，怎样验证全局覆盖？

##### 常见失分点

长窗口自动理解全部；把两者视为互斥；忽略解析。

#### 34. Agentic RAG 的适用边界

**题型：** 专项题，P1

##### 题干与约束

跨来源问题需要动态检索，何时允许 Agent 决定次数？

##### 答案骨架

1. 动态检索适合判断下一证据，稳定查询优先固定路径。
2. 定义来源、工具、进展与终止，限制跳数、耗时和费用。
3. 每轮核验证据缺口，生成结论不自动变成新事实。
4. 对照固定 RAG 衡量收益与长尾成本，失败返回证据与缺口。

##### 递进追问

一直换关键词但无新证据，如何停止？

##### 常见失分点

自主循环当必选；无预算；自身回答强化错误。

#### 35. 索引重建与 Embedding 迁移

**题型：** 专项题，P2

##### 题干与约束

不停服切换 Embedding，如何上线与回滚？

##### 答案骨架

1. 独立新索引，记录模型、预处理、维度与源版本，避免混用空间。
2. 回填后追平增量，核对数量、删除、版本和权限。
3. 影子评测后灰度，查询编码器与索引作为一组配置切换。
4. 保留回滚窗口并持续传播删除和撤权，再回收旧索引。

##### 递进追问

回填期间文档删除，回滚如何仍遵守删除要求？

##### 常见失分点

只换索引不换编码器；无增量追平；回滚恢复删除内容。

## 4. Agent 决策与任务规划

#### 36. Agent 与 Workflow 的选择

**题型：** 专项题，P0

##### 题干与约束

一个任务 80% 路径固定、20% 需要判断，如何决定自治程度？

##### 答案骨架

1. Workflow 由应用预定义流程，Agent 由模型在允许范围选择下一动作；实际系统可混合。
2. 固定规则和高风险状态迁移交给确定性流程，开放问题定位与方案探索可引入 Agent。
3. 比较成功率、可测性、成本和维护复杂度，不能因有 LLM 调用就称为 Agent。
4. 自治部分设工具边界、预算、完成标准与人工入口，按实际收益扩大范围。

##### 递进追问

开放路径后来变得稳定，是否应该固化为 Workflow？

##### 常见失分点

把 Agent 当固定工作流的必然升级；只比较灵活性；没有限制自主动作。

#### 37. ReAct 循环与状态

**题型：** 专项题，P0

##### 题干与约束

解释“分析、行动、观察”如何形成可控执行循环。

##### 答案骨架

1. 根据目标和当前证据决定下一动作，应用执行工具并把观察结果回传。
2. 保存目标、动作、结果、失败和剩余预算，观察应区分成功、失败与未知。
3. 不要求公开完整内部思维链，用结构化动作理由、证据和结果支撑诊断。
4. 应用验证终止条件、最大轮次与授权，不能只接受模型声称任务完成。

##### 递进追问

工具返回空结果，如何区分无数据、权限不足和执行失败？

##### 常见失分点

只讲循环图；把所有观察当事实；终止完全由模型自由决定。

#### 38. 任务拆解与完成标准

**题型：** 专项题，P0

##### 题干与约束

用户要求“调研并生成报告”，如何拆成可执行、可验证的任务？

##### 答案骨架

1. 明确报告范围、交付格式、来源要求与完成标准，先消除影响路径的歧义。
2. 按依赖、工具、执行环境与风险拆步骤，独立只读步骤可以并行。
3. 为子任务定义输入、产物、验证器和失败责任；“生成了一段文本”不自动等于完成。
4. 记录计划版本与进度，逐步展开必要细节，避免一次生成庞大但不可执行的计划。

##### 递进追问

两项子任务共享同一前置资料，如何减少重复读取与成本？

##### 常见失分点

只列自然语言清单；无依赖和验收；把规划等同于执行。

#### 39. 失败后的重规划

**题型：** 专项题，P1

##### 题干与约束

计划第一步失败，是重试、换方案还是重新规划？

##### 答案骨架

1. 分类为暂时依赖故障、参数错误、能力缺失、授权拒绝或目标不可达。
2. 可恢复故障有界重试，参数错误反馈纠正，缺权限不得通过替代路径绕过。
3. 重规划保留已验证产物、已发生副作用和未决状态，只修改受影响依赖。
4. 记录变更原因，检查新方案预算与完成标准，目标需改变时请求用户决定。

##### 递进追问

第一步已提交付款但后续失败，为什么不能简单从头重规划执行？

##### 常见失分点

任何错误都重跑；丢失已执行事实；通过换工具绕过拒绝。

#### 40. 空转识别与预算终止

**题型：** 专项题，P0

##### 题干与约束

Agent 重复调用同一工具，如何识别无进展并停止？

##### 答案骨架

1. 同时设最大步骤、总时长、费用与单工具失败上限，作为应用层止损边界。
2. 检查规范化动作、参数、观察和产物是否重复，区分正常轮询与无效循环。
3. 用证据增长、子任务完成和错误减少衡量进展，重复不等于必然空转。
4. 停止后保存可用产物、缺口和未决副作用，向用户给出下一步可行选择。

##### 递进追问

工具必须轮询十次才能完成，如何避免误判？

##### 常见失分点

只限制轮次；用不同措辞逃过检测；预算耗尽却伪报成功。

#### 41. 短期记忆、长期记忆与业务状态

**题型：** 专项题，P0

##### 题干与约束

对话历史、用户偏好和订单进度应分别存在哪里？

##### 答案骨架

1. 短期工作记忆支持当前推理和进度，受窗口与任务生命周期约束。
2. 长期记忆保存有来源、可更新的偏好或事实，可采用结构化存储与向量召回。
3. 订单和权限由业务系统保存，任务进度由执行系统保存；不能只放进自然语言记忆。
4. 按用途设置读取范围、时效、删除与审计，避免会话之间无边界共享。

##### 递进追问

记忆说订单已退款，但业务系统仍处理中，应相信哪个来源？

##### 常见失分点

所有状态向量化；历史全部灌入；把记忆当交易账本。

#### 42. 记忆写入与冲突更新

**题型：** 专项题，P1

##### 题干与约束

用户说“刚才的地址不要用了”，如何更新长期记忆？

##### 答案骨架

1. 区分用户明确陈述、模型推断和外部材料，只写入有必要且有依据的信息。
2. 记录主体、来源、时间、范围与置信类型；新地址与旧地址用版本和有效状态表达。
3. 撤销旧事实并失效召回、摘要与缓存，不能只追加一条互相矛盾的向量。
4. 不把用户偏好自动转为业务账户变更，敏感字段由确认流程和权威系统维护。

##### 递进追问

多个设备同时更新同一偏好，如何决定有效版本？

##### 常见失分点

模型抽取后无条件写入；只追加不撤销；记忆更新直接改业务资料。

#### 43. 记忆召回与污染防护

**题型：** 专项题，P1

##### 题干与约束

旧任务的错误结论被不断召回，如何阻止自我强化？

##### 答案骨架

1. 召回按用户、租户、任务范围、有效期与来源过滤，相似度不是唯一依据。
2. 区分确认事实与生成摘要，业务事实必要时从权威接口重新核验。
3. 对错误记忆撤销并追踪受影响摘要和产物，阻止撤销记录继续参与召回。
4. 评估召回必要性、误召回与污染传播，支持用户查看和纠正。

##### 递进追问

一条记忆很相关但已过期，如何保留历史解释而不影响当前决策？

##### 常见失分点

相关就可信；没有来源；删除原条目却保留派生摘要。

#### 44. 多 Agent 编排与任务协议

**题型：** 专项题，P1

##### 题干与约束

研究、写作与审查是否应该交给三个 Agent？

##### 答案骨架

1. 根据独立任务、不同工具边界和并行收益分工，先与单 Agent 或工作流比较。
2. 传递结构化目标、约束、输入引用、完成标准和结果，避免无限自由对话。
3. 编排器保存依赖与状态，处理超时、失败、取消传播及结果验收；限制循环依赖与互相等待，避免编排死锁。
4. 共享只读事实与产物引用，控制每个子任务权限和预算，审查不能仅凭自报完成。

##### 递进追问

子 Agent 超时但稍后返回，编排器如何避免重复合并结果？

##### 常见失分点

数量越多越好；无协议与责任；没有总预算。

#### 45. 多 Agent 共享资源冲突

**题型：** 专项题，P2

##### 题干与约束

两个 Agent 同时改同一文档或代码库，如何保证结果可审查？

##### 答案骨架

1. 先划分所有权与任务边界，能独立工作时使用隔离工作区和明确输入版本。
2. 修改生成带基线版本的补丁，合并时检测冲突并由指定协调方处理。
3. 共享业务资源使用版本条件更新或适当锁；受保护操作仍需独立授权。
4. 合并后执行整体验证，保留各自产物与审计，不把子任务通过等同于集成通过。

##### 递进追问

两份补丁单独测试通过但组合失败，谁负责发现和恢复？

##### 常见失分点

共享目录任意写；只加锁不定义所有权；无集成验证。

## 5. 工具、MCP 与执行环境

#### 46. 工具 Schema 与业务契约

**题型：** 专项题，P0

##### 题干与约束

设计退款工具，除参数类型外还应声明什么？

##### 答案骨架

1. 描述适用场景、非目标、对象标识、单位、必填和允许范围，避免隐含默认值。
2. 应用检查授权、归属、可退金额与状态前置条件，Schema 不能替代业务校验。
3. 明确幂等键、业务操作 ID、状态查询及结果未知语义。
4. 返回结构化成功或错误，说明哪些可修正、可重试和需要人工处理。

##### 递进追问

金额单位从元改成分，如何避免旧客户端继续误调用？

##### 常见失分点

只设计 JSON；描述和实现不一致；失败统一返回字符串。

#### 47. 工具选择与歧义治理

**题型：** 专项题，P1

##### 题干与约束

“查客户”和“查账户”名称相似，模型经常选错，如何改进？

##### 答案骨架

1. 明确工具业务边界、输入对象和适用示例，避免同义且行为不同的描述。
2. 按任务和权限减少候选，必要时先查实体再加载相关工具。
3. 构造近似意图、缺参数与负例，分开评测候选召回和最终选择。
4. 执行前检查对象类型与前置状态，错误选择不能直接产生不可逆副作用。

##### 递进追问

名称改好了但仍误选，如何区分描述问题和模型能力不足？

##### 常见失分点

只换名字；把误选都归模型；无负例。

#### 48. Tool Calling 错误恢复

**题型：** 专项题，P0

##### 题干与约束

参数错误、权限拒绝和依赖超时应怎样分别处理？

##### 答案骨架

1. 执行前校验类型、范围与权限，参数问题提供可操作的纠正信息。
2. 权限拒绝作为不可绕过边界，不能诱导模型换服务账号或替代路径。
3. 瞬时依赖错误有界重试；副作用超时先确认结果，不直接重复执行。
4. 每工具设置超时、并发隔离与错误分类，超过修复上限保留原因并结束或转人工。

##### 递进追问

模型纠正三次仍使用错误枚举，应继续反馈还是终止？

##### 常见失分点

所有错误重试；无限纠错；把拒绝当工具不可用。

#### 49. MCP 协议与应用责任

**题型：** 专项题，P1

##### 题干与约束

MCP 接入降低了什么成本，哪些责任仍属于应用？

##### 答案骨架

1. Host 管理模型交互与信任策略，Client 与 Server 协商能力并交换协议消息。
2. Server 可暴露 Tools、Resources 与 Prompts，能力由协议与实际协商决定，不保证每项都存在。
3. 工具发现与调用统一契约，模型选择和应用执行仍需校验、授权、审计与预算。
4. JSON-RPC 协议错误与工具执行错误应区分；标准接入不自动提供业务幂等或安全授权。

##### 递进追问

工具 annotations 声称只读，客户端能否直接免除风险检查？

##### 常见失分点

把 MCP 当 Agent 框架；接入就默认可信；混淆协议与业务责任。

#### 50. MCP 工具发现与版本变化

**题型：** 专项题，P1

##### 题干与约束

远程 Server 动态增删工具，如何管理发现缓存和在途调用？

##### 答案骨架

1. 记录协商版本与能力，完整处理 `tools/list` 分页，不只读取第一页。
2. 在支持时处理工具列表变更通知，并以适当刷新策略补足断线期间变化。
3. 将名称、Schema 与来源绑定，变更后重新验证兼容；在途任务记录使用的契约。
4. 工具消失、字段变更或策略收紧时明确失败和恢复，不能按旧权限默默继续。

##### 递进追问

旧 Schema 生成的参数遇到新 Server，如何判断能否重试？

##### 常见失分点

发现结果永久缓存；忽略分页；把同名工具当同一可信实现。

#### 51. 工具授权与用户身份传播

**题型：** 专项题，P0

##### 题干与约束

Agent 代用户操作多个系统，如何避免服务账号越权？

##### 答案骨架

1. 明确用户、租户、应用与委托范围，执行层按目标资源和动作鉴权。
2. 使用最小范围且有生命周期的凭据，凭据留在执行器，不作为模型输入。
3. 验证受众与授权范围，跨系统按需要换取目标凭据，不任意转发令牌。
4. 高风险动作审批绑定具体参数，记录主体、授权依据与执行结果；撤权后重校验。

##### 递进追问

用户有查看权限但应用账号有删除权限，模型建议删除时谁决定？

##### 常见失分点

服务账号覆盖用户权限；凭据放 Prompt；只在会话开始鉴权。

#### 52. 沙箱与代码执行隔离

**题型：** 专项题，P1

##### 题干与约束

Agent 能执行代码，如何隔离文件、网络和资源？

##### 答案骨架

1. 按任务或租户创建受限环境，明确可读写路径、进程、网络出口和资源配额。
2. 密钥不进入模型或任意执行进程；依赖安装、宿主挂载与外部访问按策略限制。
3. 记录执行输入、镜像或环境版本、退出状态与产物，限制时间、CPU、内存和输出大小。
4. 清理执行环境与临时数据，隔离方案按威胁模型选择，容器本身不等于完整安全边界。

##### 递进追问

任务生成无限日志但 CPU 不高，哪项配额应触发？

##### 常见失分点

只用容器无出口控制；挂载全部宿主目录；没有清理和资源上限。

#### 53. 浏览器 Agent 的状态验证

**题型：** 专项题，P1

##### 题干与约束

页面点击后超时，如何判断是否已经提交业务操作？

##### 答案骨架

1. 用当前可见页面状态、稳定定位与对象标识执行，防止基于旧截图重复点击。
2. 点击后读取业务确认、状态或查询入口，页面视觉变化不一定代表交易成功。
3. 不确定时核验结果，再决定是否重试；涉及发送、付款或删除需执行前授权。
4. 把页面内容视为不可信数据，限制下载、导航与文件上传范围，保留可审计证据。

##### 递进追问

按钮点击后页面刷新失败，但订单已创建，如何避免再创建？

##### 常见失分点

固定坐标反复点；超时就再提交；把网页文字当用户指令。

#### 54. Coding Agent 的执行与验证

**题型：** 专项题，P1

##### 题干与约束

Agent 修改代码后声称已修复，系统如何验证？

##### 答案骨架

1. 读取项目约束和当前变更，限定文件与目标，保留用户已有修改。
2. 在隔离或明确归属的工作区生成可评审补丁，执行环境限制权限与网络。
3. 按风险运行相关测试、构建或诊断，记录命令、退出状态和证据，未运行检查明确说明。
4. 提交、推送、合并与部署采用独立授权策略，测试通过不自动授予发布权限。

##### 递进追问

测试修改为永远通过，如何用外部验收发现“修复”无效？

##### 常见失分点

相信自报完成；覆盖用户修改；把生成补丁等同交付成功。

#### 55. 工具结果契约与不可信内容

**题型：** 专项题，P0

##### 题干与约束

远程工具返回结构化字段、长文本和报错信息，如何消费？

##### 答案骨架

1. 按输出契约解析并检查状态、来源、版本和业务标识，传输成功不等于执行成功。
2. 限制大小、格式和资源引用访问，截断明确标注，必要时分页或引用读取。
3. 文本中的新指令不改变用户授权；工具自述可信、只读或完成不能替代验证。
4. 保留可操作错误分类与关联 ID，敏感字段脱敏后再供模型和日志使用。

##### 递进追问

返回状态是失败但文本说“已全部完成”，应怎样判断？

##### 常见失分点

只看 HTTP 200；未经校验传给模型；无输出预算。

## 6. 状态、异步执行与可靠性

#### 56. 长任务的异步执行与恢复

**题型：** 核心案例，P0，45 分钟

##### 目标与规模假设

任务执行 2–20 分钟，包含多轮模型调用和可写业务工具。支持一万项在途任务，客户端可断线，Worker 可能随时重启；需进一步明确到达率和完成时间分布。

##### 不可协商约束

- 任务不依赖单个 HTTP/SSE 连接存活。
- 工具副作用不能因进程恢复而盲目重做。
- 用户能查询最终与未知状态，人工修复有记录。

##### 关键决策

Task、Step、Attempt 如何划分；执行权和 Checkpoint 如何配合；任务落库、消息和外部副作用如何收敛。

##### 答案骨架

1. 接入层鉴权、幂等创建 Task 并可靠投递，返回任务 ID 与状态查询入口。
2. Worker 获取有效执行权，记录 Step 和每次 Attempt，固定配置版本并保存中间产物。
3. 外部写操作使用稳定业务幂等键，未知结果先查询；步骤确认后提交进度。
4. 状态与结果独立持久化，事件流用于展示；恢复、取消、审批和修复有显式状态及审计。

##### 故障注入

工具已写成功但 Worker 在提交步骤前宕机。先说明恢复处理，再假设旧 Worker 恢复并与新 Worker 竞争执行。

##### 评价要点

能解释权威事实、执行权与去重责任；不声称消息队列天然保证端到端 exactly-once。

#### 57. Agent 状态机与并发更新

**题型：** 专项题，P0

##### 题干与约束

取消、完成和超时同时更新任务，如何保持合法状态？

##### 答案骨架

1. 区分 Task 生命周期与 Step/Attempt，定义待执行、运行、等待审批、恢复中及明确终态。
2. 状态迁移有前置状态、版本条件和操作者，使用事务或条件更新防止覆盖。
3. 取消请求与已生效取消分开，超时与业务结果未知分开，明确竞态优先级。
4. 保存迁移事件和原因，终态后迟到结果仍可用于核验副作用，不任意覆盖终态。

##### 递进追问

取消请求先到、业务完成后到，展示什么状态取决于哪些事实？

##### 常见失分点

一个 status 包含所有语义；任意覆盖；状态存在就认为副作用已停止。

#### 58. Checkpoint 与步骤提交时机

**题型：** 专项题，P0

##### 题干与约束

步骤结果、产物和进度分别写入，Checkpoint 应何时推进？

##### 答案骨架

1. Checkpoint 表示已验证并可恢复的进度，不是“发出请求”的位置。
2. 先确认产物持久化与步骤结果，再提交进度；同库记录尽量事务化。
3. 外部副作用不能与本地记录原子提交时，先保存操作意图和幂等键，用结果查询收敛。
4. 恢复验证 Checkpoint 引用的产物和版本，避免进度存在但产物丢失。

##### 递进追问

工具成功但 Checkpoint 更新失败，恢复时应从哪里判断？

##### 常见失分点

执行前推进进度；只存步骤号；假设所有写入原子。

#### 59. Worker 租约与执行权

**题型：** 专项题，P1

##### 题干与约束

旧 Worker 长暂停后恢复，新 Worker 已接管任务，如何防并行写？

##### 答案骨架

1. 用有过期时间的租约分配执行权，心跳续租与进展监控分开。
2. 分配单调执行代次或 Fencing Token，任务更新检查当前持有者与版本。
3. 资源或执行网关支持时拒绝旧代次操作；仅在任务库加锁无法阻止已发出的外部请求。
4. 外部系统不支持 Fencing 时配合幂等、串行化执行或对账，明确剩余竞态。

##### 递进追问

心跳正常但步骤十分钟无进展，应续租还是终止？

##### 常见失分点

worker_id 当执行代次；锁过期等于旧执行停止；没有下游边界。

#### 60. 请求、任务与工具幂等

**题型：** 专项题，P0

##### 题干与约束

重复点击、消息重复和工具重试应分别使用什么键？

##### 答案骨架

1. 请求键在租户与操作范围内唯一，同键不同参数拒绝，避免错误复用。
2. Task 去重保证同一请求只建一个逻辑任务，Attempt 可多次但逻辑步骤不变。
3. 工具副作用使用稳定业务键或操作 ID，重试保留它，最终系统负责去重。
4. 保存状态和首次有效结果；生成不可复现时优先复用已存结果，而非重新生成冒充幂等。

##### 递进追问

去重记录过期后旧消息再次投递，如何避免再次产生副作用？

##### 常见失分点

每次重试生成新键；只按消息 ID；没有范围与保存期限。

#### 61. 工具成功但响应丢失

**题型：** 专项题，P0

##### 题干与约束

发送通知请求超时，对方可能已经发送，接下来如何处理？

##### 答案骨架

1. 记录结果未知，保留业务操作 ID，超时不能直接解释成失败。
2. 有幂等与查询能力时查询或携同键重试，区分接收、执行与最终完成。
3. 无此能力时评估重复成本，采用对账、人工核验或限制自动重试。
4. 展示处理中或待核验状态，记录责任与收敛期限，不能让模型猜测成功。

##### 递进追问

第三方不支持查询也不支持幂等，能承诺绝不重复且绝不丢失吗？

##### 常见失分点

超时立即重发；本地去重当下游去重；没有未知状态。

#### 62. 任务落库与消息可靠投递

**题型：** 专项题，P1

##### 题干与约束

任务写库成功但发 MQ 失败，如何避免永远不执行？

##### 答案骨架

1. 同事务写 Task 与 Outbox，由投递器重试发布，监控未发送积压。
2. 发送成功但标记失败会重复，消费者以逻辑任务和步骤幂等，不能只信消息一次到达。
3. 消费确认与步骤持久化配合，处理抢占失败、毒消息和任务已终结情形。
4. 定期对账待执行任务、Outbox 与队列，配置重放和修复入口。

##### 递进追问

消息发送成功但 Outbox 未标记，重发后如何处理？

##### 常见失分点

库与 MQ 裸双写；宣称 Outbox 消除所有重复；无积压监控。

#### 63. 取消与超时后的副作用

**题型：** 专项题，P0

##### 题干与约束

用户点击取消时工具仍在执行，如何定义取消语义？

##### 答案骨架

1. 区分停止等待、停止未来步骤、请求取消下游及撤销已完成动作。
2. 保存取消意图，Worker 在安全点和写操作前检查，限制新动作启动。
3. 已发出请求可能继续成功，保留晚到结果，查询核验并按业务规则补偿。
4. 返回取消请求已接收或确认停止的实际状态，不承诺所有操作瞬间撤回。

##### 递进追问

取消后仍完成付款，应如何展示与后续处理？

##### 常见失分点

关闭 SSE 就取消；本地超时等于下游停止；抛弃迟到结果。

#### 64. 人工审批与恢复执行

**题型：** 专项题，P0

##### 题干与约束

用户审批后十分钟才执行，此时价格或权限变化，如何处理？

##### 答案骨架

1. 审批绑定动作、对象、参数摘要、目标版本、审批人和期限，不能泛化为无限授权。
2. 待审批状态持久化，使用幂等决定与通知，恢复时不重新规划被批准动作。
3. 执行前重验权限、资源状态与参数，超出批准范围重新审批或拒绝。
4. 审批和执行分别审计，撤回与超时有定义，不能把批准当操作已成功。

##### 递进追问

审批的是退款 100 元，模型恢复后建议 200 元，如何阻止？

##### 常见失分点

只存 approved=true；恢复时自由改参数；不检查审批有效期。

#### 65. 部分成功与补偿边界

**题型：** 专项题，P1

##### 题干与约束

更新资料成功、发送邮件失败，是否应回滚整个任务？

##### 答案骨架

1. 按业务承诺区分主事实和附带通知，失败不一定要求撤销主操作。
2. 定义每步可逆性与补偿条件，外部邮件、付款等不能当普通数据库回滚。
3. 保存已完成、失败和补偿状态，补偿也需幂等、重试及人工入口。
4. 用户看到部分成功与待处理事项，最终状态依据事实而非模型总结。

##### 递进追问

补偿本身失败，任务应如何继续收敛？

##### 常见失分点

所有动作可回滚；补偿等于逆操作；忽略补偿失败。

#### 66. 超时、重试与重试放大

**题型：** 专项题，P0

##### 题干与约束

SDK、网关和 Worker 都重试，如何避免一次失败变成数十次调用？

##### 答案骨架

1. 明确连接、首 Token、单步与总 Deadline，给后续恢复保留时间。
2. 确定重试责任层和总预算，指数退避、抖动并遵守可用的重试提示。
3. 对瞬时故障重试，参数和授权错误直接处理；写操作先确认未知结果。
4. 记录尝试次数、费用和调用放大，达到上限终止或降级；幂等不自动消除重复计费。

##### 递进追问

模型流式返回一半后失败，重新请求如何避免前端拼出两份答案？

##### 常见失分点

每层三次重试；无限延长总超时；只防重复副作用不看费用。

#### 67. 模型与工具限流熔断

**题型：** 专项题，P0

##### 题干与约束

供应商返回 429，内部工具也出现延迟，如何保护系统？

##### 答案骨架

1. 按请求、输入输出 Token、并发和租户治理，配额口径以供应商实际规则为准。
2. 各工具设独立并发、队列与超时，限制 Agent 扇出，保护内部业务服务。
3. 持续错误或慢调用触发隔离与熔断，半开探测受控恢复。
4. 降级不伪造事实：知识缺失可拒答，写操作保留处理中；429 重试也受总预算限制。

##### 递进追问

一个大客户耗尽共享 TPM，其他客户如何获得服务？

##### 常见失分点

只按 QPS；失败工具用默认成功；恢复瞬间全量重试。

#### 68. 流式断线与结果恢复

**题型：** 专项题，P1

##### 题干与约束

用户断线后重连到另一副本，如何继续看到同一任务？

##### 答案骨架

1. 任务、结果与事件独立保存，连接只负责投递，不决定执行生命周期。
2. 事件带任务 ID 和递增序号；原生 EventSource 可用 Last-Event-ID，其他客户端自行保存游标。
3. 重连先鉴权，再从持久化事件重放，客户端按序去重；保留期过后返回快照或最终结果。
4. 完成后有确定的终态与查询入口，事件保存与状态写入的失败需可对账。

##### 递进追问

游标对应事件已过期，如何避免用户只收到后半段内容？

##### 常见失分点

只存单副本内存；重连重新启动任务；SSE 自带业务持久化。

#### 69. 死信、卡住任务与人工修复

**题型：** 专项题，P1

##### 题干与约束

任务心跳正常但无进展，或反复失败进入死信，如何修复？

##### 答案骨架

1. 区分等待依赖、死循环、执行权异常和毒输入，用步骤、租约与进展联合判断。
2. 保存错误、操作 ID、版本、预算与失败尝试，死信需可检索与人工处置。
3. 重放前核验已发生副作用与当前权限，选择恢复步骤而非整任务盲跑。
4. 修复操作有权限、并发保护、审计与验收，批量恢复控制速率避免二次冲击。

##### 递进追问

修复人员与自动恢复同时操作，如何防止重复执行？

##### 常见失分点

只看心跳；无上下文死信；人工直接改 status。

#### 70. Webhook 与完成通知

**题型：** 专项题，P1

##### 题干与约束

任务完成后通知外部系统，如何处理重试和乱序？

##### 答案骨架

1. 完成事实先持久化，再可靠投递通知，通知失败不改变已完成业务结果。
2. 固定事件 ID、任务版本与类型，验签、防重放，接收端幂等并拒绝状态倒退。
3. 限制回调目标、超时与重试预算，持续失败进入补发或人工队列。
4. 提供查询入口与通知水位，敏感内容通过授权链接读取，不在回调中泄露全部数据。

##### 递进追问

完成通知先到，较早的运行中通知后到，接收方如何处理？

##### 常见失分点

通知失败就重做任务；不验证回调目标；没有版本和去重。

## 7. 性能、容量与成本

#### 71. 高并发 Agent 容量设计

**题型：** 核心案例，P0，45 分钟

##### 目标与规模假设

活动期间十万用户在一分钟内提交任务，任务平均调用模型 4 次、工具 6 次。需要先澄清输入输出长度、耗时分布、可排队时间与供应商配额，不能把十万用户直接解释成十万次同时推理。

##### 不可协商约束

- 在有限模型与工具配额下提供明确的接收、排队、拒绝和完成语义。
- 一个租户的突发不能耗尽所有客户资源。
- 缓存、路由与降级不能破坏权限和业务事实。

##### 关键决策

入口与实际调用压力如何换算；哪些任务同步、哪些异步；如何保护尾延迟和内部工具。

##### 答案骨架

1. 估算入口约 1667 请求/秒；按调用次数、Token 和时长推导模型、工具及在途压力，加入重试余量。
2. 短交互可流式同步，长任务持久化后排队；设置接收配额、租户调度与等待上限。
3. 对可复用只读任务启用有权限与版本约束的缓存，按评测路由模型，限制工具并发。
4. 分开测排队、TTFT、完成时间、成功率与费用，验证突发、长任务和恢复流量。

##### 故障注入

供应商可用 TPM 减半，说明限流与排队调整；随后单独加入内部工具 P99 升高，说明隔离和可接受降级。

##### 评价要点

估算能改变设计，不把 MQ 当无限容量，不把 SSE 或异步化当实际吞吐提升保证。

#### 72. 语义缓存与误命中治理

**题型：** 专项题，P0

##### 题干与约束

“可以报销”和“不可以报销”很相似，如何避免缓存错误复用？

##### 答案骨架

1. 相似检索只提供候选，时间、主体、条件、否定与权限共同决定答案是否等价。
2. 缓存绑定租户、授权范围、上下文、知识和策略版本，副作用结果不按语义重执行。
3. 用近似但不同答案的负例校准阈值，高风险任务禁用或增加精确校验。
4. 监控误命中、质量和每成功任务成本，知识更新、撤权与删除触发失效。

##### 递进追问

命中率上升但投诉增加，为什么不能继续降低阈值？

##### 常见失分点

只有相似度和 TTL；共享个性化答案；缓存代替授权检查。

#### 73. 精确缓存与前缀缓存

**题型：** 专项题，P1

##### 题干与约束

结果缓存、语义缓存与 Prefix Caching 分别复用什么？

##### 答案骨架

1. 精确结果缓存复用完整响应，键包含会影响结果的输入、版本、权限和上下文。
2. 语义缓存对近似问题复用答案，需要额外等价性与误命中评测。
3. 前缀缓存复用共同输入前缀的计算或 KV，不返回旧答案；vLLM APC 主要减少 Prefill 而非 Decode 时间。
4. 根据服务实现检查缓存键、隔离和失效，缓存命中不意味着无计费或永远保留。

##### 递进追问

固定 Prompt 前放随机时间戳，会怎样影响共同前缀复用？

##### 常见失分点

三个缓存混为一谈；前缀缓存认为能减少所有生成时间；忽略隔离。

#### 74. 模型路由与质量门禁

**题型：** 专项题，P0

##### 题干与约束

简单任务用小模型，如何判断哪些任务必须升级？

##### 答案骨架

1. 用任务类型、输入长度、工具复杂度、语言、风险和数据约束建立规则或分类路由。
2. 在切片样本上验证小模型可接受范围，路由器误判也进入评测。
3. 低质量、校验失败或能力不足时可升级，限制重复尝试与总费用。
4. 记录路由原因、模型、版本和结果，不能把供应商失败自动当小模型可替代。

##### 递进追问

路由器本身调用大模型，如何判断是否仍然节省成本？

##### 常见失分点

只按问题长度；模型自报“简单”作依据；无升级和质量门禁。

#### 75. LLM Serving 性能优化

**题型：** 专项题，P2

##### 题干与约束

自托管模型吞吐低，如何选择 Batching、量化和缓存？

##### 答案骨架

1. 先区分排队、Prefill、Decode 与通信瓶颈，测 TTFT、TPOT、吞吐和显存。
2. Continuous Batching 动态调度不同阶段请求，提高利用率，也需控制长短请求干扰。
3. 分页 KV 管理、前缀复用、INT8/FP8/INT4 等受支持量化和适用的投机解码按目标负载比较收益与质量。
4. 调整并行方式、上下文和批预算，压测必须满足延迟 SLO，不能只报最大 Tokens/s。

##### 递进追问

大批量提高吞吐但首 Token 变慢，应如何选配置？

##### 常见失分点

GPU 利用率高就认为用户体验好；量化无损假设；无真实长度分布。

#### 76. GPU 显存与并发估算

**题型：** 专项题，P2

##### 题干与约束

70B 模型能支持多少长对话并发，如何给出有边界的估算？

##### 答案骨架

1. 先确认精度、模型结构、GPU 数量、并行方式、上下文和输出长度，不能只凭型号给固定数字。
2. 权重初估为参数量乘每参数字节，额外加入量化元数据、运行缓冲与内存余量。
3. 普通 KV 粗估为 `2 × 层数 × KV 头数 × 头维度 × Token 数 × 字节数`，再考虑并发和具体分片。
4. 根据剩余显存求候选并发，再用真实负载验证碎片、调度与延迟，特殊结构需另建模型。

##### 递进追问

使用 GQA 后，为什么不能继续用 Query 头数估 KV 大小？

##### 常见失分点

只算权重；忽略长度与余量；显存放得下等于满足延迟。

#### 77. 背压、队列与公平调度

**题型：** 专项题，P1

##### 题干与约束

任务到达快于处理速度，如何防队列持续膨胀？

##### 答案骨架

1. 设置接收上限、排队时限、容量水位与拒绝语义，积压不能被当作成功完成。
2. 按租户和任务等级公平调度，限制单任务工具扇出，防止长任务长期占满资源。
3. 根据可用 Token、Worker 和工具能力控制出队，不能只靠入口限流。
4. 排队超时、取消和恢复任务有明确处理，监控最老任务、等待分位数与饥饿。

##### 递进追问

高优先级任务持续到达，低优先级任务如何避免永久等待？

##### 常见失分点

无限队列；只扩 Worker 不看供应商配额；只有队列长度没有等待指标。

#### 78. 成本拆解与预算控制

**题型：** 专项题，P1

##### 题干与约束

流量不变但费用翻倍，如何诊断和限制成本？

##### 答案骨架

1. 拆分输入、输出、缓存相关计费、Embedding、Rerank、工具、存储与裁判费用。
2. 按任务、租户和版本比较轮次、长度、重试、路由与误命中，而非只看总 Token。
3. 执行前估算或预留预算，执行中逐步扣减和调整；预留与最终结算幂等并核对账单。
4. 压缩、缓存、路由和允许延迟的批处理都以质量门禁为前提，优化每成功任务成本。

##### 递进追问

用户同时启动多个任务，如何避免各自检查余额都通过却合计超支？

##### 常见失分点

只统计模型单次费用；无并发预留；低成本通过率高但失败任务更贵。

#### 79. 多供应商 Fallback

**题型：** 专项题，P1

##### 题干与约束

主模型失败时切换供应商，需要检查哪些兼容性？

##### 答案骨架

1. 核对结构化输出、工具消息、窗口、媒体与拒绝语义，接口兼容不等于行为一致。
2. 切换仍需符合数据位置与授权要求，不能因故障发送给未批准供应商。
3. 定义请求尚未输出、部分输出和工具已执行时的不同策略，副作用保持业务键。
4. 用业务回归和故障演练验证备用能力，记录切换原因、版本与额外费用。

##### 递进追问

主模型已输出一半，备用模型给出不同结论，前端如何交付？

##### 常见失分点

所有模型可互换；两个输出直接拼接；跨供应商绕过数据约束。

#### 80. AI Gateway 架构

**题型：** 核心案例，P2，45 分钟

##### 目标与规模假设

统一接入三家模型供应商，为 100 个应用提供路由、配额和计量，峰值每秒 500 次模型请求。需澄清流式占比、Token 分布、租户和服务等级。

##### 不可协商约束

- 密钥与租户信息不进入模型可见上下文。
- 路由符合数据策略，计费和重试可归因。
- 网关失败有明确降级，不能形成无保护的全量旁路。

##### 关键决策

公共协议与供应商能力差异如何表达；配额一致性如何取舍；控制面失效时执行面如何工作。

##### 答案骨架

1. 数据面鉴权、策略检查、准入、适配与流式转发，控制面管理模型、凭据和配置版本。
2. 路由依据能力、质量、成本和故障；租户配额区分请求、Token、并发及金额。
3. 多副本网关使用可用的预算与限流机制，明确强一致校验和短时本地额度的取舍。
4. 记录逻辑请求与尝试，核对用量；配置故障使用有期限的已验证快照，敏感策略失效时拒绝。
5. 可复用请求采用精确或语义缓存，键包含权限与版本；审计与脱敏按策略执行，流式转发需明确审核和断线边界。

##### 故障注入

配额存储不可用，说明可继续与必须拒绝的请求；随后单独加入供应商流式中断，说明尝试和计量处理。

##### 评价要点

处理适配差异、预算与可用性，而非只画反向代理；不把 Fallback 当无条件放行。

## 8. 评测、可观测与发布治理

#### 81. AI 应用的测试分层

**题型：** 专项题，P0

##### 题干与约束

LLM 输出不固定，哪些部分仍能写确定性测试？

##### 答案骨架

1. 授权、状态迁移、幂等、解析和预算使用单元与性质测试，断言真实业务不变量。
2. 工具 Schema、错误与消息适配使用契约测试；沙箱、队列和存储使用集成测试。
3. 模型行为通过带验收标准的任务评测、多次运行与人工抽查衡量，不要求逐字相同。
4. 高风险流程做端到端测试与故障注入，Mock 工具用于控制失败，真实环境验收验证集成。

##### 递进追问

模型文本改变但业务行为正确，测试应失败吗？

##### 常见失分点

声称 AI 无法单元测试；只做字符串快照；Mock 完全替代集成。

#### 82. Golden Set 与数据泄漏

**题型：** 专项题，P0

##### 题干与约束

如何构建回归集，避免一遍遍调 Prompt 后“满分”却线上失败？

##### 答案骨架

1. 从授权的真实任务、反馈和故障形成样本，记录输入、环境、预期事实与评分依据。
2. 覆盖高频、难例、无答案、权限、长任务与工具失败，按业务切片评估。
3. 调优集与独立验收集分开，近重复、同一会话和关联文档需防泄漏。
4. 对新分布持续补样本，版本化数据与标签，报告样本量、无效样本和不确定性。

##### 递进追问

100 条样本全通过，为什么不能直接声明线上成功率 100%？

##### 常见失分点

只用简单手写题；测试答案进入 Prompt；反复在验收集调优。

#### 83. Agent 轨迹与任务成功评测

**题型：** 专项题，P0

##### 题干与约束

Agent 最终答案正确但曾越权调用工具，应如何评分？

##### 答案骨架

1. 分开评估最终结果、过程安全、效率和可恢复性，结果正确不能抵消非法行为。
2. 用业务状态、产物和授权记录断言成功，禁止动作、重复副作用与未决状态单列。
3. 容许多个有效轨迹，不强制唯一调用顺序；依赖与必须验证的步骤保留约束。
4. 在可重置环境多次运行，统计成功率、步骤、费用和方差，避免残留状态污染实验。

##### 递进追问

两个 Agent 路径不同都完成任务，如何公平比较？

##### 常见失分点

只评最终文本；轨迹逐字匹配；不清理工具状态。

#### 84. LLM-as-a-Judge 校准

**题型：** 专项题，P1

##### 题干与约束

模型裁判与人工不一致，能否直接用于发布门禁？

##### 答案骨架

1. 定义评分准则、标签和可见证据，固定裁判模型与 Prompt；裁判也需要评测。
2. 对比独立人工标签，检查位置、长度、风格与自偏好，换序或重复评分发现不稳。
3. 无效标签不能静默当负例，报告有效样本和无效数；按误判代价检查混淆矩阵。
4. 若校准目标是复现人工标签，不能把该目标标签给裁判；参考答案式评分则提供独立任务答案，并保留验收集。
5. 高风险门禁采用规则和人工复核，裁判未校准时只作诊断信号。

##### 递进追问

大多数样本都合格，总准确率很高为何仍可能漏掉严重失败？

##### 常见失分点

裁判更大就当可靠；调优和验证同一批；用待预测人工标签泄漏答案。

#### 85. AI Trace 与敏感数据治理

**题型：** 专项题，P0

##### 题干与约束

如何关联模型、检索、工具与异步任务，同时避免日志泄密？

##### 答案骨架

1. 关联 request、task、step、attempt 和 Trace，异步链路保留父子或因果关系。
2. 记录版本、模型、Token、排队、延迟、工具结果和状态，保留必要诊断引用。
3. 输入输出按字段脱敏、最小化和权限控制，原始内容隔离保存或不采集，密钥不入日志。
4. 采样保留关键故障、版本和业务切片，评测信号回连具体观察；观测上报失败不拖垮执行。

##### 递进追问

只有错误最终答案，缺少当时检索版本，为什么难以复现？

##### 常见失分点

只有 HTTP Trace；全量明文记录；不同尝试混成一次调用。

#### 86. Agent 故障定位与止血

**题型：** 专项题，P1

##### 题干与约束

耗时从 5 秒变成 30 秒，错误率也上升，如何排查？

##### 答案骨架

1. 确认受影响任务、租户和时间，比较近期模型、Prompt、索引、工具与调度变更。
2. 分解排队、模型、检索、工具、重试和步骤数，定位首次偏离，而非只看最终错误。
3. 延迟先查等待、TTFT/TPOT 与工具尾延迟，错误先查证据、Schema、权限和状态。
4. 按证据回滚、限流或暂停高风险动作，随后核验副作用、重放可恢复任务并复盘。

##### 递进追问

模型延迟不变但工具调用数翻倍，应该先扩 GPU 吗？

##### 常见失分点

全部归为模型幻觉；先全量重跑；止血后不核对业务事实。

#### 87. AI 服务 SLI、SLO 与告警

**题型：** 专项题，P1

##### 题干与约束

HTTP 200 很稳定但任务无法完成，如何定义服务目标？

##### 答案骨架

1. 根据用户旅程定义接收率、排队、按时完成、最终成功及结果新鲜度，写清分母与窗口。
2. 请求成功、任务成功和业务正确分开，取消、拒绝、未知结果不能随意排除。
3. 质量信号可能延迟且来自抽样，标明覆盖和不确定性，不能当瞬时精确 SLI。
4. 用预算消耗和用户影响告警，基础资源指标辅助定位；高风险错误单独触发处置。

##### 递进追问

把超时任务从分母排除后成功率提高，为什么指标失真？

##### 常见失分点

HTTP 200 当任务成功；只看 GPU 利用率；样本评分当全量实时事实。

#### 88. 模型、Prompt 与索引发布

**题型：** 专项题，P1

##### 题干与约束

同时存在模型、Prompt、工具与索引版本，如何发布和回滚？

##### 答案骨架

1. 定义可兼容的配置组合，任务记录所用模型、Prompt、工具契约和索引版本。
2. 单元、契约与任务回归通过后影子或小流量灰度，安全和关键业务切片设门禁。
3. 在线比较质量、尾延迟、费用和副作用，明确停止条件与回滚目标。
4. 在途任务固定版本或经过迁移，索引回滚仍遵守当前撤权和删除，历史审批不因升级扩权。

##### 递进追问

回滚模型后旧工具 Schema 已不兼容，应如何处理在途任务？

##### 常见失分点

只回滚 Prompt；没有配置组合；平均质量遮住危险切片。

## 9. 安全、隐私与多租户

#### 89. Prompt Injection 防御

**题型：** 专项题，P0

##### 题干与约束

网页或文档要求 Agent 忽略用户限制并发送内部资料，如何防护？

##### 答案骨架

1. 标明用户指令与外部内容的信任边界，网页、文档、图片文字和工具结果均可携带注入。
2. 模型识别与内容检测降低风险，但工具执行必须由独立授权和数据策略控制。
3. 限制读写与网络权限，把敏感操作绑定用户批准的对象和参数，必要时隔离读写任务。
4. 测试间接注入、跨工具传播和数据外泄，审计拒绝与误杀，不声称单一 Prompt 能彻底防御。

##### 递进追问

恶意文档自称“企业管理员已批准”，执行层如何判断？

##### 常见失分点

只写“忽略恶意指令”；模型自己授权；只测用户直接输入攻击。

#### 90. SSRF 与数据外泄防护

**题型：** 专项题，P0

##### 题干与约束

Agent 可访问 URL 和上传文件，如何防止访问内网或把数据发送到外部？

##### 答案骨架

1. 限制协议、端口、目标域与地址范围，阻止未授权环回、私网、元数据地址及相关 IPv6 地址。
2. 检查解析、实际连接与每次重定向，防 DNS Rebinding；以出口代理或网络策略补充应用校验。
3. 上传、邮件、回调与浏览动作执行数据出口授权，允许目标不代表允许发送所有数据。
4. 回调验签与防重放，记录来源、目标、敏感字段和批准范围，不能只校验 URL 字符串。

##### 递进追问

白名单域重定向到 `169.254.169.254`，哪一层应拒绝？

##### 常见失分点

只查域名；只禁一个 IP；网络允许就默认数据可外传。

#### 91. PII 与模型数据最小化

**题型：** 专项题，P0

##### 题干与约束

Agent 需要处理客户资料，如何减少不必要的数据暴露？

##### 答案骨架

1. 先定义任务所需字段，只向模型发送必要数据，凭据和完整账户资料留在受控执行层。
2. 脱敏或假名化后保留受保护映射，必要时由工具恢复字段，注意关联数据仍可能识别主体。
3. 分别制定模型供应商、工具、日志、记忆和产物的访问及留存策略。
4. 数据训练使用、地域、合同和删除能力按实际政策与约定核实，不凭“企业版”名称推断。

##### 递进追问

电话号码已遮盖但姓名和地址完整，是否已充分去标识化？

##### 常见失分点

脱敏一次认为全链路安全；映射公开；供应商数据处理政策未经核实。

#### 92. Guardrails 与误杀治理

**题型：** 专项题，P0

##### 题干与约束

审核既要拦截危险输出，也不能大面积阻断正常业务，如何设计？

##### 答案骨架

1. 输入、检索结果、模型输出与动作分别定义风险和检查点，输出流交付前考虑审核时机。
2. 规则、分类器、语义校验和人工组合，授权与业务不变量保持确定性检查。
3. 按风险选择拒绝、脱敏、澄清或转人工，安全依赖故障时规定可继续范围。
4. 用标注样本统计误杀与漏放，保存脱敏原因并支持申诉，调整阈值需回归验证。

##### 递进追问

流式内容已经发送后才被判危险，应怎样改进交付策略？

##### 常见失分点

只有敏感词；所有审核故障都放行；把内容审核等同动作授权。

#### 93. 多租户隔离与资源公平

**题型：** 专项题，P1

##### 题干与约束

1000 家企业共享平台，如何保证数据、执行和费用不串租户？

##### 答案骨架

1. 租户身份来自可信认证上下文，数据、任务、索引、缓存、记忆与产物访问均绑定它。
2. 查询范围和工具凭据不能由模型自由指定，高敏感租户按需要升级独立存储或执行环境。
3. 隔离密钥、沙箱、出口与管理权限，观测和客服后台同样实施租户边界。
4. 配额、排队、费用归因和负载测试覆盖热点租户，避免大客户造成邻居噪声。

##### 递进追问

共享缓存键漏了 tenant_id，但模型回答看起来正常，如何发现？

##### 常见失分点

只在表里加租户字段；相信模型传入租户；后台和日志无隔离。

#### 94. 对话、记忆与派生数据删除

**题型：** 专项题，P1

##### 题干与约束

用户要求删除对话和记忆，如何防止摘要、向量或旧备份再次恢复它们？

##### 答案骨架

1. 用数据血缘枚举源记录、摘要、向量、缓存、产物、日志与供应商副本。
2. 先阻止读取和召回，再可靠传播删除，记录范围、期限与处理状态，法定保留另行说明。
3. 删除事件有版本保护，重建索引和恢复备份时重放删除清单，防止数据复活。
4. 按备份和供应商能力明确实际删除窗口及限制，完成后核验可见路径与审计证据。

##### 递进追问

在线已删但离线重建使用一周前快照，如何避免再次写回？

##### 常见失分点

只删会话表；所有系统即时物理删除的无依据承诺；忽略备份。

## 10. 端到端系统设计案例

#### 95. 企业知识助手

**题型：** 核心案例，P0，45 分钟

##### 目标与规模假设

两万员工查询制度、项目文档与结构化业务资料。文档持续更新且权限细分，交互希望几秒内得到首段有依据内容；需澄清最终完成目标与知识更新时限。

##### 不可协商约束

- 文档回答带可访问引用，业务实时状态来自权威接口。
- 不向无权用户暴露内容、存在性或历史缓存。
- 没有证据时明确缺口，不用通用知识假装内部制度。

##### 关键决策

知识问答与业务查询如何路由；权限撤销如何生效；多轮指代与来源冲突如何处理。与第 21 题相比，本题重点是产品承诺和多来源融合。

##### 答案骨架

1. 入口建立用户身份与会话，判断查知识、查实时事实还是需要澄清。
2. 文档走带权限的 RAG，结构化事实走只读工具，保留来源时间与适用范围。
3. 汇总时核验引用、冲突与字段，敏感场景交付前复核，结果与流式事件可恢复。
4. 按部门、语言、无答案和撤权场景评测，监控新鲜度、解决率、延迟与费用。

##### 故障注入

用户转部门后旧缓存仍存在，说明处理；再假设制度文档与实时 API 冲突，说明权威归属。

##### 评价要点

根据事实类型选路径，说明权限和时效，而非所有数据都塞向量库。

#### 96. 客服与工单 Agent

**题型：** 核心案例，P0，45 分钟

##### 目标与规模假设

日均十万会话，提供政策解答、工单创建和进度查询，可转人工。用户身份与可执行动作依渠道不同，需要明确自动处理范围和转人工响应要求。

##### 不可协商约束

- 不编造退款、赔付和处理完成承诺。
- 工单创建幂等，用户资料最小化。
- 人工接管后明确执行权，自动 Agent 不继续冲突操作。

##### 关键决策

固定服务流程与模型判断边界；转人工触发与上下文交接；工具超时后的事实核验。

##### 答案骨架

1. 鉴权和意图识别后进入适当流程，政策来自可追溯知识，状态来自业务工具。
2. 高风险动作通过业务规则与审批，创建工具有幂等键和查询入口。
3. 转人工传递用户目标、证据、已做动作和未决状态，记录接管与恢复条件。
4. 评测解决率、错误承诺、重复工单、人工负担及费用，投诉不能只归为回答风格。

##### 故障注入

工单创建超时但实际已成功，说明重试策略；随后客户再次提问，说明如何保持身份与同一事项关联。

##### 评价要点

定义业务承诺和人机交接，避免用兜底文案掩盖未知状态。

#### 97. Coding Agent 平台

**题型：** 核心案例，P1，45 分钟

##### 目标与规模假设

支持百个团队并行处理代码任务，每项任务可运行 30 分钟，交付补丁和验证记录。需澄清仓库大小、依赖下载、执行环境与是否允许提交、推送和部署。

##### 不可协商约束

- 保留用户已有修改，跨任务工作区与凭据隔离。
- 仓库文本和工具输出不能扩大任务授权。
- 结果包含真实验证证据，失败或未运行检查明确标注。

##### 关键决策

工作区生命周期、补丁集成责任、测试执行与审查门禁；读写和网络权限如何约束。

##### 答案骨架

1. 固定基线、任务目标与项目约束，分配隔离工作区和受限执行环境。
2. 检索代码、规划变更、生成补丁，子任务按文件与责任分工，共享修改需协调。
3. 执行相关测试与构建，保存命令和产物，审查检查需求、回归与测试是否有效。
4. 集成前重验基线与冲突，外部写操作按授权执行，清理环境时保留可恢复产物。

##### 故障注入

任务测试通过但目标分支随后改变，说明集成验证；再假设两个任务修改同一函数，说明冲突责任。

##### 评价要点

区分补丁生成、验证、审查与发布，不把自主编码解释成无限权限。

#### 98. 研究与报告 Agent

**题型：** 核心案例，P1，45 分钟

##### 目标与规模假设

针对一个用户问题读取最多 200 个来源，生成带引用的报告，允许执行 20 分钟。明确研究范围、时间边界、来源类型与预算，不能用来源数量代替质量。

##### 不可协商约束

- 区分事实、推断和未验证结论，引用可追溯。
- 外部资料不触发未经授权的动作或数据上传。
- 超时仍交付可用产物及明确缺口，不伪装完整覆盖。

##### 关键决策

研究问题如何拆解；来源去重和可信度如何管理；并行检索收益与最终整合责任。

##### 答案骨架

1. 明确子问题与证据要求，分配可并行的只读任务，限制检索跳数与 Token。
2. 保存来源、读取时间、版本与定位，识别转载、冲突和失效内容。
3. 按主张组织证据，再生成报告和引用，重要结论由核验步骤检查。
4. 持久化进度与产物，结束条件包括覆盖、预算和进展；评测准确、完整与引用支持。

##### 故障注入

重要来源不可访问，说明报告缺口；随后单独加入某网页中的恶意上传指令，说明阻断路径。

##### 评价要点

说明证据质量、终止和产物恢复，不把抓取成功率当研究成功率。

#### 99. 有副作用的业务操作 Agent

**题型：** 核心案例，P0，45 分钟

##### 目标与规模假设

Agent 根据用户请求创建订单、申请退款或发送通知，每秒接收 100 项操作请求。需要澄清可自动执行的范围、审批规则与第三方幂等能力。

##### 不可协商约束

- 模型建议不是业务授权，金额与状态由权威系统检查。
- 重复请求不能重复创建同一业务操作，未知结果可查询与核验。
- 不可逆动作不能被描述成已自动回滚。

##### 关键决策

哪些步骤使用确定性流程；审批绑定与状态变化如何处理；外部操作记录与本地进度如何一致。

##### 答案骨架

1. 解析意图后生成动作提案，验证身份、对象、金额、前置状态与权限。
2. 所需审批绑定参数与版本，执行前重验；不满足条件返回新提案或拒绝。
3. 保存操作意图与稳定业务键，通过权威工具执行，结果未知时查询或对账。
4. 分开记录任务与业务结果，通知异步可靠投递，取消和补偿按业务可逆性处理。

##### 故障注入

退款已成功但响应丢失，说明收敛；再假设审批后可退金额变化，说明执行前检查。

##### 评价要点

覆盖授权、幂等、未知结果与人工恢复，不以模型输出决定交易终态。

#### 100. 多租户 Agent 平台

**题型：** 核心案例，P2，45 分钟

##### 目标与规模假设

向 1000 家企业开放 Agent 配置、知识接入、工具和异步执行，租户有不同数据策略与服务等级。需澄清峰值、长任务比例、供应商、私有部署和灾难恢复要求。

##### 不可协商约束

- 身份、知识、缓存、记忆、工具凭据和产物按租户授权。
- 配置发布可追溯，运行任务不被未审核的新配置悄然改变。
- 预算、执行隔离和删除要求贯穿平台，不由模型自行遵守。

##### 关键决策

控制面与执行面边界；共享与专属资源划分；平台能力如何复用而不跨越租户策略。

##### 答案骨架

1. 控制面管理身份、配置、版本、工具注册与策略，执行面承载队列、Worker、沙箱与状态。
2. AI Gateway 管模型路由与计量，知识与工具访问保留用户委托范围，敏感租户可用专属资源。
3. 任务固定兼容配置组合，采用分层配额与公平调度；故障域隔离，控制面不可用有有限快照策略。
4. 建设数据血缘、删除、评测发布、Trace 和恢复入口，按租户验证服务目标与成本归因。
5. 从最小可运营平台演进，达到隔离、容量或组织瓶颈再拆能力，不默认每个框都做独立服务。

##### 故障注入

一个租户造成积压，说明公平调度；随后单独加入错误工具配置已灰度，说明停止、回滚与在途处理。

##### 评价要点

把前面机制落实到平台边界、故障域和运营责任，而非只列框架与中间件。
