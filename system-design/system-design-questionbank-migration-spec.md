# 系统设计面试题库迁移与整理规格

**状态：待评审**  
**日期：2026-10-08**

## 目标

将可靠系统设计书稿中的系统设计题库迁移为本仓库独立维护的公开学习资料，并以更紧凑、以内容为中心的形式呈现。迁移后读者应能从系统设计入口直接找到题目、完成练习，并通过关键追问和复盘要点检查自己的回答。

正式文件为：

`system-design/question-bank/system-design-interview-practice.md`

## 范围

### 保留

- 题库中的题目、题号、题干、答案、关键设计取舍、追问、示例和代码。
- 核心案例、约束变体、快问快答、模拟面试和按能力导航。
- 对理解方案有帮助的容量估算、状态机、失败处理、幂等、对账与可观测性内容。
- 已有公开的外部技术资料链接；链接文字改为独立题库语境。

### 移除

- 书籍结构标识，例如“附录 D”“原第 N 章”“书稿”“重构前”等。
- 源书稿路径、行号、迁移来源、覆盖审计及仅用于编辑过程的说明。
- 面向书稿章节的交叉引用；如内容确有必要，改为本仓库内的题目链接或独立的参考链接。
- 每题重复且不直接增加学习价值的固定小节：
  - 候选人作答任务
  - 推荐作答顺序
  - 评分锚点
  - 复盘清单

### 不在本次处理

- 不改写题目的技术结论或扩充新的系统设计主题。
- 不改变题号；已有锚点与外部引用应继续可定位。
- 不删除历史详细材料，只整理其标题、顺序和表达，使其成为题目答案的一部分。

## 文档结构

文档采用以下固定层级，避免每题堆叠元信息：

```text
# 系统设计面试题库

使用说明与训练方式
按能力导航

## 核心案例
### Q-SD-CORE-01：题目名称
#### 场景与约束
#### 作答要点
#### 追问

## 约束变体
## 快问快答
## 模拟面试
## 参考资料
```

题目中的元信息仅在它会影响作答时保留，并合并到“场景与约束”。例如规模、时限、业务边界和明确的故障情境应保留；“题型”“难度”“建议用时”等标签仅在训练入口集中说明，不在每道题重复。

“作答要点”按读者真正需要组织：先明确目标和权威状态，再说明主链路、异常路径、关键取舍与观测恢复机制。原有答案中的完整推导、表格和代码示例保持在该小节中，不拆为机械重复的小标题。

## 迁移规则

1. 以 `/Users/xianguiwang/Projects/wxquare.github.io/books/reliable-system-design/src/appendix/system-design-questionbank.md` 为内容基线。
2. 迁移后文件不得包含 `附录 D`、`原第`、`books/reliable-system-design`、`迁移来源`、`覆盖审计` 等书稿遗留文本。
3. 删除当前损坏文件开头混入的 `Warning: truncated output`、工具统计文字和半截代码；内容从完整题库标题开始。
4. 旧文件 `system-design/question-bank/system-design-questionbank.md` 将被新文件替代，不保留重复副本。
5. 更新 `system-design/README.md` 及仓库中所有指向旧文件的链接，使其指向新文件。
6. 链接到同文档题目的锚点应在格式整理后逐一存在；外部链接不在本次迁移中改写其技术内容。

## 验收条件

- 新文件开头为独立的“系统设计面试题库”标题和简短使用说明。
- 文件中不存在截断工具输出、书稿路径或书籍章节遗留标识。
- 所有 `Q-...` 题号保持唯一，且题号集合与源文件一致。
- 核心题目具有“场景与约束、作答要点、追问”三个可读入口；缺少其一时，保留真实内容而不创建空标题。
- 系统设计目录入口、题库内链接和根目录链接均可访问新文件。
- `python3 tools/check_markdown_consistency.py` 通过。

## 风险与处理

源文件很长，格式机械替换可能误删代码、链接或表格中的有效内容。整理将按标题和固定小节边界进行，并在完成后比较题号集合、代码围栏数量和本地链接。对于无法自动归类的历史详细材料，优先保留内容并将其置于对应题目或“参考资料”，不因格式目标删除技术信息。
